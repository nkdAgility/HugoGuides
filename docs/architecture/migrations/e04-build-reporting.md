# E04 build and report foundation

Status: development implementation; E04 acceptance remains open.

The root build.ps1 now runs platform contract checks and publishing-operation tests, builds the independent reference site, and validates the artifact. Versions runs before importing test dependencies. Stage selects Prepare, Build or Validate; the bare command runs all three. Every default run receives a fresh directory under .processing/platform-build. Explicit OutputPath supports CI stage handoff and refuses existing output during Build.

The existing platform Build Site job now calls this root script for Build and Validate. GitHub continues to install Hugo and transport artifacts. Version/environment selection, workflow-level reporting and the disabled deployment job are still legacy orchestration; main.yaml is not yet the final thin shared workflow. The canary target is retained solely for that existing platform workflow; consumer policy still uses local/preview/production.

The build uses a generated configuration overlay instead of replacing tokens in source templates/configuration. It places the merged hosting configuration in the actual site artifact, enforces the 500 MB limit, checks JSON and rejects unresolved build tokens. Local, preview, production and legacy canary builds passed; local produced 76 files and the other configurations 85 each. No deployment was enabled. Existing reference warnings remain recorded, including unavailable preview.hugoguides.org and existing template/i18n warnings.

Get-GuideAssessment combines Core publication, wrapper and guide observations into the assessment v1 contract. It collects independent findings even if one edition cannot be parsed. Wrapper runtime readiness remains unknown until artifact evidence exists. Prepare can pass its own checks while explicitly listing runtime checks for the later Validate stage; it does not approve a deployment.

OpenGuidePlatform.PowerShell.Build renders the same result as escaped Markdown and writes JSON/Markdown to an immutable per-run directory. The development .build/Prepare-GuideSite.ps1 entry point writes reports before failing on assessment blockers. Missing/invalid policy and configuration inputs now produce blocked reports. The Hugo adapter collects production configuration directly with printZero, plus the active target languages; caller-supplied effective JSON remains available for isolated tests. A missing policy digest is represented as null only in failed/blocked assessments, never fabricated. The contract rejects pass with an unknown digest.

Validation: 97 Pester tests, including schema-valid aggregated failures and preservation of failed reports, plus seven skill checks and 19 contract checks. A preview assessment fixture rejects effective production enablement of Minionese. The Markdown table includes severity, scope, subject, diagnostic and remediation, followed by every observed guide/edition/language.

Remaining E04 work: consumer stage orchestration; report delivery failure diagnostics; Actions/PR publication with stale-run protection; effective catalogue fallback; runtime route/anchor/download/exclusion validation; deployment identity and post-deploy Verify. No consumer has adopted this candidate.
The test gate now requires Pester's overall Result to be Passed, including discovery/container status. The real Hugo adapter observed Kanban production Minionese disabled=true without altering the site. [Synthetic report example](e04-example-prepare.md) demonstrates the shared Markdown format; it is not a live consumer assessment.

Artifact follow-up: shared Test-GuideArtifact now collects missing route/download, prohibited path, JSON, token and size findings. Build creates a file-hash identity bound to source commit, dirty-state flag and target; Validate rejects modified inventories/bytes or mismatched commit/target. These are integrity checks, not independent trusted attestation. CI retains Site-Evidence separately and writes an Actions summary even when the build never reached validation. The preview root build passed with 85 files. Policy-to-artifact path mapping, anchors and live deployment checks remain outstanding; forbidden resources are checked only for explicitly supplied paths.

Freshness follow-up: Prepare now queries the installed and Go-resolved latest module version in read-only mode. A different pin, active replacement or unavailable registry/tool evidence produces a warning rather than an automatic upgrade or fabricated pass. Go @latest semantics are used, not an assumption about the newest GitHub release label. The live Kanban check resolved installed/latest v0.8.4 and left go.mod and the consumer working tree unchanged. Three regression tests cover current, differing, replacement and unavailable cases.

CI context follow-up: environment selection now lives in Get-GuideBuildContext with a local/Actions output adapter. PR and merge-queue events always resolve to isolated canary targets, including release-labelled PRs. Stable and Preview push semantics remain; selection does not authorize deployment. Workflow values enter through environment variables rather than interpolated PowerShell source. The obsolete token-era blob/baseURL outputs and duplicated summary job are removed. Prepare now runs the root Prepare stage (contracts, publishing tests and distributed skill checks) before Build can start. The disabled deployment job no longer re-merges configuration or modifies the validated artifact. Five new tests and a full preview build passed locally (85 files); shared workflow packaging and the trusted governance gate remain later work.

Toolchain follow-up: Prepare and Build both inspect the actual Hugo executable output and require Extended >= 0.146.0. An unavailable/unrecognised, standard or older executable fails before rendering. Four regression tests cover those cases; the full local preview build passes on Hugo 0.164.0 Extended with 85 artifact files. CI for 852eead passed Prepare, Build and validation, with deployment skipped.

Summary delivery follow-up: consumer Prepare can append its schema-validated assessment to GITHUB_STEP_SUMMARY (or an explicit SummaryPath) using the same Markdown renderer as local output. Local report storage failure no longer suppresses console/Actions findings. Delivery failures have REPORT_DELIVERY_FAILED diagnostics and fail the command while preserving the underlying pass/fail/blocked assessment. Five regression tests cover blocked findings, existing summary preservation, invalid success evidence, I/O failure and occupied immutable local storage. PR comment publication and stale-run protection are still outstanding. GitHub runs for 846af75 remained queued during this work; local validation is not represented as CI success.

PR reporting follow-up: a development append-only publisher now validates assessment schema, compares the open PR head to the assessed commit, checks again before POST, and identifies comments by run/attempt/target/stage/commit. It never overwrites other reports. Retries recognize an exact visible comment from the expected reporter; API failures remain delivery failures. Six regression tests pass and a read-only rehearsal against PR35 reached the WhatIf publication boundary without posting. Workflow serialization and the independent trusted reporting boundary remain E06/E07 integration work; merge-commit evidence must not be relabelled as head evidence. All workflows at 172c138 passed; the new publisher has not posted live assessments.

Route resolution follow-up: artifact expectations now resolve both literal file paths and directory index paths from the actual inventory, including dotted edition identifiers. URL path segments are decoded once so encoded Persian routes resolve to unchanged Unicode filenames. Encoded separators, traversal, malformed escapes, query/fragment syntax and ambiguous authority paths are rejected. Three new regressions and the full preview-target build pass (90 tests, 85 artifact files). This does not infer consumer route policy, change Hugo URLs, or validate heading anchors. All workflows for the preceding publisher commit 86f138f passed.

Duplicate-output gate: Build now requests Hugo printPathWarnings; Validate consumes the retained log and rejects duplicate target ownership with HUGO_DUPLICATE_TARGETS. The real isolated Kanban production log is rejected (12 duplicate paths). Reference-only Guide2 translation pages no longer claim the shared aliases also owned by Guide1; both mandatory/reference and full preview builds pass with the same 85-file inventory. This deliberately fixes reference wrapper data, not Hugo module internals or any consumer site. Two new tests pass (92 total). The user's subsequent decision retains existing legacy compatibility without extending it; consumer integration must distinguish its frozen existing declarations from new duplicate claims.

Legacy compatibility decision: existing /download/, /downloads/ and /translationsdirectory/ aliases are retained only where already implemented. No new ownership decision or new-language requirement is introduced. Translation scaffolding now omits those three inherited legacy aliases while preserving source files, existing translations and unrelated guide-specific aliases. The regression suite covers inline alias YAML and unchanged source bytes. This does not edit any consumer language file.

Missing-evidence follow-up: Get-GuideArtifactAssessment returns structured blocked results when the artifact or Hugo log cannot be inspected, with null size/file metrics rather than fabricated zero values. Artifact failures and identity mismatches are collected together when inputs are available. Root Validate writes artifact-validation.json even when Build has not produced its output, then fails. Four adapter regressions, a direct Validate-without-Build negative check and the full preview build pass (97 tests, 85 files).
